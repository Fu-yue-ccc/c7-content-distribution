# 从来没用过 GitHub？这篇教你 30 分钟发布第一个项目

> 作为一个三个月前连 GitHub 是什么都不知道的人，我把自己踩坑后总结的最简流程写出来，保证新手也能跟着做。

---

三个月前，我对 GitHub 的认知是零。

我知道它是个"程序员网站"，但注册页面全是英文，一堆看不懂的按钮，每次想学习都被劝退。

直到课程要求我们必须把项目放到 GitHub 上，我才硬着头皮开始研究。

结果发现——**从注册账号到发布第一个项目，其实只需要 30 分钟。**

这篇文章把完整流程拆解成傻瓜式步骤，每一步告诉你点哪里、输入什么。跟着做，你也能拥有自己的第一个开源项目。

---

## 一、GitHub 到底是什么？

一句话解释：**GitHub 是一个存放代码的网站，也是全球最大的程序员社交平台。**

你可以把它理解为"代码版的网盘 + 简历"：

- 你的每个项目都有一个独立页面
- 所有修改历史都会被记录
- 别人可以查看、下载、改进你的代码
- 你的 GitHub 主页就是你的技术简历

**面试官真的会看你的 GitHub。** 一个有完整项目记录的账号，比简历上写十句"熟练掌握编程"都有说服力。

---

## 二、第一步：注册账号（5 分钟）

### 1. 打开官网

访问 [github.com](https://github.com)，点击右上角的 **Sign up**。

### 2. 填写信息

- **邮箱**：用你常用的邮箱（QQ邮箱、163邮箱都可以）
- **密码**：设置一个安全的密码
- **用户名**：这是最重要的！建议用姓名拼音或英文名，比如 `zhangsan-sias`

> 用户名一旦确定就很难改，而且会出现在你的所有链接里，所以认真想一个。

### 3. 验证邮箱

注册后 GitHub 会给你发一封验证邮件，点击邮件中的链接完成验证。

### 4. 完成注册

登录后你会看到 GitHub 的主页面，这一步就完成了。

---

## 三、第二步：创建仓库（3 分钟）

"仓库"（repository，简称 repo）就是一个项目文件夹。

### 1. 点击新建

登录后，点击页面右上角的 **+** 号，选择 **New repository**。

### 2. 填写仓库信息

- **Repository name**（仓库名）：填你的项目名，比如 `my-first-project`
- **Description**（描述）：一句话说明项目做什么，可选但建议填
- **Public/Private**：选择 **Public**（公开，别人才能看到）
- **Add a README file**：**勾选这个！** README 是项目的说明文档

### 3. 点击创建

点击绿色的 **Create repository** 按钮，仓库就建好了。

你会看到一个页面，里面已经有一个 README.md 文件。

---

## 四、第三步：写 README（10 分钟）

README.md 是别人打开你的仓库后看到的第一个文件，非常重要。

### 一个好的 README 应该包含：

```markdown
# 项目名称

> 一句话说明项目做什么

## 功能
- 功能一
- 功能二

## 快速开始
说明怎么安装和运行

## 使用示例
放截图或代码示例

## 技术栈
用了什么语言、框架、工具

## License
开源协议（建议 MIT）
```

### 怎么编辑？

在仓库页面点击 `README.md` 文件，然后点击右上角的**铅笔图标**（Edit this file），直接在网页上编辑。

编辑完后拉到页面底部，点击绿色的 **Commit changes** 按钮保存。

> Commit 就是"提交一次修改"的意思，每次修改都会被记录。

### 不会写？让 AI 帮你

把你的项目信息告诉 AI：

> "我做了一个 XX 项目，功能是 XX，用了 XX 技术。帮我写一个完整的 README.md。"

AI 会生成一个格式规范的初稿，你根据实际情况修改就行。

---

## 五、第四步：上传文件（5 分钟）

如果你的项目有代码文件，需要上传到仓库。

### 方法一：网页上传（最简单）

1. 进入仓库主页
2. 点击 **Add file** → **Upload files**
3. 把文件拖拽到虚线区域（可以一次拖多个）
4. 点击底部 **Commit changes**

### 方法二：Git 命令行（推荐学习）

先安装 Git：
- Windows：从 [git-scm.com](https://git-scm.com) 下载安装
- Mac：终端运行 `xcode-select --install`

然后在终端执行：

```bash
# 把仓库下载到本地
git clone https://github.com/你的用户名/仓库名.git

# 进入文件夹
cd 仓库名

# 把你的文件复制进去后，执行三步：
git add .
git commit -m "添加项目文件"
git push
```

第一次使用会要求你登录，按提示操作即可。

> 网页上传适合少量文件，命令行适合频繁修改。新手先用网页版，熟练后再学命令行。

---

## 六、第五步：Fork 别人的项目（5 分钟）

Fork 就是把别人的仓库复制一份到你自己的账号下。

### 什么时候需要 Fork？

- 想学习别人的代码
- 想在别人项目基础上修改
- 想给开源项目做贡献

### 怎么 Fork？

1. 打开别人的仓库页面（比如老师指定的项目）
2. 点击页面右上角的 **Fork** 按钮
3. 选择你的账号作为目标
4. 等待几秒钟，你的账号下就出现了这个仓库

### Clone 到本地

Fork 后，把你自己账号下的仓库下载到电脑：

```bash
git clone https://github.com/你的用户名/项目名.git
cd 项目名
```

然后你就可以在本地浏览和修改代码了。

---

## 七、第六步：添加开源协议（2 分钟）

开源协议（LICENSE）说明别人可以怎么使用你的代码。

最简单的方式：

1. 进入仓库主页
2. 点击 **Add file** → **Create new file**
3. 文件名输入 `LICENSE`
4. 右侧会出现 **Choose a license template** 按钮
5. 选择 **MIT License**（最宽松、最常用）
6. 点击 **Review and submit** → **Commit changes**

MIT 协议的意思是：任何人都可以免费使用、修改、分发你的代码，只需要保留版权声明。

## 八、新手最容易犯的 5 个错误

### 错误 1：把 API Key 或密码上传到 GitHub

**这是最严重的错误！** 公开仓库里的所有人都能看到你的密钥。

- 永远不要把密码、API Key、私钥写进代码
- 用 `.env` 文件存放敏感信息（并添加到 .gitignore）
- 如果不小心传了，立刻去对应平台重置密钥

### 错误 2：README 是空的或太简单

一个没有 README 的仓库，别人完全不知道你的项目做什么。

哪怕项目很小，也要写清楚：做什么、怎么用、技术栈。

### 错误 3：上传一堆无关文件

不要把系统文件、临时文件、依赖库都传上去。

创建一个 `.gitignore` 文件，列出不需要上传的内容：

```
__pycache__/
venv/
.env
.DS_Store
*.pyc
```

### 错误 4：Commit 信息写"aaa"、"修改"

每次 Commit 的信息应该说明你改了什么，比如：

- ✅ "添加登录页面"
- ✅ "修复地图标记点击无响应的问题"
- ❌ "aaa"
- ❌ "修改"

### 错误 5：只创建仓库但不维护

GitHub 的价值在于持续更新。哪怕每周只提交一次，也比创建后就不管好。

## 九、我的第一个项目

我发布的第一个项目是一个本地大模型驱动的地图生成器：

- 输入地点名称和数量
- AI 生成结构化地点数据
- 自动渲染交互式地图
- 全程本地运行，零 API 费用

从完全不懂 GitHub 到把这个项目完整发布，我花了大约一个下午。

中间踩了不少坑（比如第一次 push 时不知道怎么认证），但每解决一个问题都在进步。

**最重要的是：我真的开始做了，而不是一直停留在"想学"的阶段。**

## 十、30 分钟行动清单

如果你现在就想开始，按这个清单做：

- [ ] 注册 GitHub 账号（5 分钟）
- [ ] 创建一个公开仓库，勾选 README（3 分钟）
- [ ] 编辑 README，写清楚项目信息（10 分钟）
- [ ] 上传你的项目文件（5 分钟）
- [ ] 添加 MIT LICENSE（2 分钟）
- [ ] 把仓库链接分享给朋友（5 分钟）

完成后，你就拥有了第一个公开的 GitHub 项目。

---

## 写在最后

很多新手（包括我）迟迟不敢开始用 GitHub，是因为觉得它"太专业了，我还不够格"。

但事实是：**没有人会因为你的项目简单而嘲笑你，所有人都是从第一个 Hello World 开始的。**

GitHub 上有大量初学者的练习项目，开源社区对新手非常友好。

你不需要成为编程大神才能使用 GitHub。你只需要：
1. 开始做一个项目
2. 把它放到 GitHub 上
3. 持续改进

**最好的学习时间是三个月前，其次是现在。**
