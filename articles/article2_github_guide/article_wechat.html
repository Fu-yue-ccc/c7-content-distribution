从来没用过 GitHub？这篇教你 30 分钟发布第一个项目

作为一个三个月前连 GitHub 是什么都不知道的人，我把踩坑后总结的最简流程写出来，保证新手也能跟着做。

三个月前，我对 GitHub 的认知是零。

我知道它是个"程序员网站"，但注册页面全是英文，一堆看不懂的按钮，每次想学习都被劝退。

直到课程要求必须把项目放到 GitHub 上，我才硬着头皮开始研究。

结果发现——从注册账号到发布第一个项目，其实只需要 30 分钟。

一、GitHub 到底是什么？

一句话解释：GitHub 是存放代码的网站，也是全球最大的程序员社交平台。

你可以把它理解为"代码版的网盘 + 简历"：

· 每个项目都有独立页面，修改历史全记录

· 别人可以查看、下载、改进你的代码

· GitHub 主页就是你的技术简历

面试官真的会看你的 GitHub。一个有完整项目记录的账号，比简历上写十句"熟练掌握编程"都有说服力。

二、第一步：注册账号（5 分钟）

1. 打开官网：访问 github.com，点击右上角 Sign up。

2. 填写信息：

· 邮箱：常用邮箱即可（QQ邮箱、163邮箱都行）

· 密码：设置安全密码

· 用户名：最重要！建议姓名拼音或英文名，如 zhangsan-sias

用户名会出现在所有链接里，一旦确定很难改，认真想一个。

3. 验证邮箱：GitHub 会发验证邮件，点击链接完成。

4. 完成注册：登录后看到主页面，这步完成。

三、第二步：创建仓库（3 分钟）

"仓库"（repository，简称 repo）就是一个项目文件夹。

1. 点击右上角 + → New repository

2. 填写信息：

· Repository name：项目名，如 my-first-project

· Description：一句话说明项目做什么

· 选择 Public（公开）

· 勾选 Add a README file

3. 点击绿色 Create repository，仓库建好。

四、第三步：写 README（10 分钟）

README.md 是别人打开仓库看到的第一个文件，非常重要。

一个好的 README 应包含：项目名称、一句话说明、功能列表、快速开始、使用示例、技术栈、License。

怎么编辑？点击 README.md 文件，点右上角铅笔图标，网页直接编辑，底部点 Commit changes 保存。

不会写？让 AI 帮你：把项目信息告诉 AI，它会生成格式规范的初稿，你修改就行。

五、第四步：上传文件（5 分钟）

方法一：网页上传（最简单）

1. 仓库主页点 Add file → Upload files

2. 文件拖到虚线区域，点 Commit changes

方法二：Git 命令行（推荐学习）

先安装 Git（git-scm.com 下载），然后：

git clone https://github.com/用户名/仓库名.git
cd 仓库名
git add .
git commit -m "添加项目文件"
git push

网页上传适合少量文件，命令行适合频繁修改。新手先用网页版。

六、第五步：Fork 别人的项目（5 分钟）

Fork 就是把别人仓库复制一份到你账号下，适合学习别人代码或在其基础上修改。

1. 打开别人仓库页面，点右上角 Fork

2. 选择你账号为目标，等待几秒完成

Fork 后 clone 到本地：

git clone https://github.com/你的用户名/项目名.git

七、第六步：添加开源协议（2 分钟）

开源协议（LICENSE）说明别人可以怎么用你的代码。

1. Add file → Create new file，文件名输 LICENSE

2. 点右侧 Choose a license template

3. 选择 MIT License（最宽松最常用）→ Commit

MIT 协议：任何人可免费使用、修改、分发你的代码，只需保留版权声明。

八、新手最容易犯的 5 个错误

错误 1：把 API Key 或密码上传到 GitHub

这是最严重的错误！公开仓库里所有人都能看到你的密钥。

· 永远不要把密码、API Key、私钥写进代码

· 用 .env 文件存放敏感信息（并添加到 .gitignore）

· 如果不小心传了，立刻去对应平台重置密钥

错误 2：README 是空的或太简单

一个没有 README 的仓库，别人完全不知道项目做什么。哪怕项目很小，也要写清楚：做什么、怎么用、技术栈。

错误 3：上传一堆无关文件

创建一个 .gitignore 文件，列出不需要上传的内容：

__pycache__/
venv/
.env
.DS_Store
*.pyc

错误 4：Commit 信息写"aaa"、"修改"

每次 Commit 的信息应该说明你改了什么：

✅ "添加登录页面"、"修复地图标记点击无响应的问题"

❌ "aaa"、"修改"

错误 5：只创建仓库但不维护

GitHub 的价值在于持续更新。哪怕每周只提交一次，也比创建后就不管好。

九、我的第一个项目

我发布的第一个项目是一个本地大模型驱动的地图生成器：

· 输入地点名称和数量

· AI 生成结构化地点数据

· 自动渲染交互式地图

· 全程本地运行，零 API 费用

从完全不懂 GitHub 到把项目完整发布，我花了大约一个下午。中间踩了不少坑（比如第一次 push 时不知道怎么认证），但每解决一个问题都在进步。

最重要的是：我真的开始做了，而不是一直停留在"想学"的阶段。

30 分钟行动清单

□ 注册账号（5分钟）

□ 创建公开仓库，勾选 README（3分钟）

□ 编辑 README 写清项目信息（10分钟）

□ 上传项目文件（5分钟）

□ 添加 MIT LICENSE（2分钟）

□ 把链接分享给朋友（5分钟）

写在最后

很多新手迟迟不敢开始，是觉得"太专业了，我还不够格"。但事实是：没人会因为项目简单嘲笑你，所有人都从 Hello World 开始。

你不需要成为大神才能用 GitHub。开始做一个项目，放上去，持续改进。最好的学习时间是三个月前，其次是现在。
