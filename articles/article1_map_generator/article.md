# 零 API 费用！我用本地大模型做了一个 AI 地图生成器

> 你没看错——不需要花一分钱调用 GPT，也不需要联网，AI 就能在你的电脑上生成一张交互式地图。

---

大家好，我是一名人工智能专业的大一学生。

最近课程要求我们做一个项目：**输入一个地点名称，AI 自动生成带分类标记的交互式地图。**

正常思路是调用 GPT-4 的 API，让它返回地点的经纬度和描述，然后用地图库渲染。

但问题来了——**API 要花钱，而且我的数据要发到别人的服务器上。**

作为一个经济紧张的学生，我决定换个思路：**让大模型完全在本地运行。**

结果，我真的做出来了。这篇文章把完整过程写出来，你照着做也能跑通。

---

## 一、先看效果

最终生成的地图长这样：

- 打开一个 HTML 文件
- 地图上有 12 个彩色标记点，每个点一种分类颜色
- 点击标记，弹出地点名称、描述、坐标
- 可以缩放、拖拽，左下角有分类图例
- 底图是 OpenStreetMap（免费开源）

我用的是自己学校——郑州西亚斯学院的真实数据，包含莫斯科红场、欧洲街、法国园等 12 个校园地标。

**整个过程零 API 费用，AI 完全在我笔记本上运行。**

---

## 二、用了什么工具

### 1. Ollama：本地大模型运行器

[Ollama](https://ollama.com) 是一个可以让你在本地电脑上跑大模型的工具，安装极其简单。

- Windows/Mac：官网下载安装包，双击安装
- Linux：一行命令搞定

安装后，在终端输入一行命令就能下载模型：

```bash
ollama pull gemma4:e4b
```

### 2. Gemma 4：Google 开源大模型

我用的是 Google 的 Gemma 4，Apache 2.0 开源协议，可以免费商用。

选它有三个原因：

- **支持函数调用**（function calling），这是做 Agent 的关键
- **支持结构化输出**，可以强制返回 JSON
- **体积小**，e4b 版本普通笔记本就能跑

### 3. Folium：Python 地图库

[Folium](https://python-visualization.github.io/folium/) 是一个 Python 交互式地图库，基于 Leaflet.js。

几行代码就能生成带标记的地图，不需要写前端。

## 三、核心思路：四步流水线

整个项目的工作流程是这样的：

```
用户输入地点名称和数量
    ↓
本地 Gemma 4 生成结构化 JSON
    ↓
自动验证坐标和字段完整性
    ↓
Folium 渲染成交互式 HTML 地图
```

### 第一步：让 AI 输出 JSON

关键是写好 System Prompt（系统提示词），强制模型只返回 JSON：

```python
system_prompt = """You are a geography assistant.
You ALWAYS respond with valid JSON only.
No markdown, no explanations, no code blocks.

Return a JSON array of locations.
Each location has: name, name_zh, latitude,
longitude, description, category.
"""
```

这里有个细节：**大模型有时候会"不听话"**，在 JSON 外面包一层 markdown 代码块。

所以代码里要做清理：

```python
content = content.replace("```json", "")
content = content.replace("```", "").strip()
```

### 第二步：自动验证数据

AI 生成的坐标可能是错的（这叫"坐标幻觉"）。

我写了一个验证器，检查每个地点：

- 六个字段是否齐全
- 坐标是否是数字
- 纬度是否在 -90 到 90 之间
- 经度是否在 -180 到 180 之间
- 坐标是否在目标地点的合理范围内

验证不通过的地点会被标记出来。

### 第三步：分类着色

我定义了 12 种地点分类，每种对应一个颜色：

| 分类 | 颜色 |
|------|------|
| 校门 | 红色 |
| 地标建筑 | 蓝色 |
| 教学设施 | 绿色 |
| 体育设施 | 橙色 |
| 商业街 | 紫色 |
| 园林景观 | 青色 |

### 第四步：渲染地图

用 Folium 生成地图，添加标记、弹窗、图例、标题栏：

```python
m = folium.Map(
    location=[center_lat, center_lon],
    zoom_start=15,
    tiles="OpenStreetMap"
)

folium.Marker(
    [lat, lon],
    popup=popup_html,
    icon=folium.Icon(color=color)
).add_to(m)

m.save("map.html")
```

双击生成的 HTML 文件，浏览器打开就是交互式地图。

## 四、踩了三个大坑

### 坑 1：AI 给的坐标偏差 3.5 公里

第一次让 AI 生成学校坐标，它给了 34.40°N, 113.73°E。

我在高德地图一查，实际坐标是 34.401422°N, 113.765004°E——**经度差了 3.5 公里！**

**教训：AI 生成的精确坐标一定要用地图服务验证，不能直接信。**

后来我在代码里加了坐标范围验证，并且内置了经过人工核实的真实数据作为离线回退。

### 坑 2：模型太大，电脑带不动

我一开始想跑 26B 参数的模型，结果 8GB 内存的笔记本直接卡死。

后来换成 e4b 版本（约 5GB 内存占用），流畅运行。

**建议：**
- 8GB 内存：用 e2b 版本
- 16GB 内存：用 e4b 版本（推荐）
- 有独立显卡：可以试 26B

### 坑 3：Ollama 服务没启动

第一次运行脚本，一直提示"无法连接 Ollama"。

排查了半天才发现，Ollama 服务没在后台运行。

Windows 上检查任务栏有没有羊驼图标，Linux 上要手动运行 `ollama serve`。

## 五、离线模式：100% 可用

为了防止模型出问题，我加了一个离线模式。

不调用 AI，直接使用内置的 12 个经过人工核实的真实地点数据：

```bash
python sias_map_agent.py --offline
```

这样即使 Ollama 没装、模型没下载，也能正常生成地图。

**这个设计保证了项目 100% 可用，不会因为 AI 故障而完全瘫痪。**

## 六、从脚本到 Web App

做完本地脚本后，我又把它升级成了一个网页应用。

用户打开网页，输入地点名称，选择 Demo 模式或 AI 模式，点击生成就能看到地图。

技术栈是纯 HTML + Tailwind CSS + JavaScript + Leaflet.js，单文件零依赖。

部署到 Vercel 后，任何人打开链接就能使用——**从"我能跑"变成了"所有人都能用"。**

## 七、你可以怎么做

如果你也想做一个类似的项目，建议按这个顺序：

1. **安装 Ollama**，下载 gemma4:e4b
2. **安装依赖**：`pip install requests folium`
3. **先跑离线模式**，确认地图能正常生成
4. **再试 AI 模式**，观察模型输出
5. **验证坐标**，用高德地图核对
6. **最后部署上线**，分享给同学

整个过程 AI 辅助下大约需要半天时间。

## 写在最后

做完这个项目，我最大的感受是：**本地大模型的能力被严重低估了。**

它不需要联网、不花 API 费用、数据不离开你的设备，而且能力已经足够完成很多实际任务。

对于注重隐私和成本的场景（比如处理个人位置数据），本地模型可能比云端 API 更合适。

当然，本地模型在复杂推理上还不如 GPT-4 等大模型，但对于"生成结构化数据 + 渲染地图"这种任务，它完全够用。

**关键不是工具有多强，而是你能不能把工具组合起来解决真实问题。**
