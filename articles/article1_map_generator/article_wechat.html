零 API 费用！我用本地大模型做了一个 AI 地图生成器

你没看错——不需要花一分钱调用 GPT，也不需要联网，AI 就能在你的电脑上生成一张交互式地图。

大家好，我是一名人工智能专业的大一学生。

最近课程要求我们做一个项目：输入一个地点名称，AI 自动生成带分类标记的交互式地图。

正常思路是调用 GPT-4 的 API，让它返回地点的经纬度和描述，然后用地图库渲染。

但问题来了——API 要花钱，而且我的数据要发到别人的服务器上。

作为一个经济紧张的学生，我决定换个思路：让大模型完全在本地运行。

结果，我真的做出来了。这篇文章把完整过程写出来，你照着做也能跑通。

一、先看效果

最终生成的地图长这样：

打开一个 HTML 文件，地图上有 12 个彩色标记点，每个点一种分类颜色。

点击标记，弹出地点名称、描述、坐标。可以缩放、拖拽，左下角有分类图例。

我用的是自己学校——郑州西亚斯学院的真实数据，包含莫斯科红场、欧洲街、法国园等 12 个校园地标。

整个过程零 API 费用，AI 完全在我笔记本上运行。

二、用了什么工具

1. Ollama：本地大模型运行器

Ollama 是一个可以让你在本地电脑上跑大模型的工具，安装极其简单。Windows/Mac 官网下载安装包，Linux 一行命令搞定。

安装后，终端输入一行命令下载模型：

ollama pull gemma4:e4b

2. Gemma 4：Google 开源大模型

我用的是 Google 的 Gemma 4，Apache 2.0 开源协议，可以免费商用。选它三个原因：

· 支持函数调用（function calling），做 Agent 的关键

· 支持结构化输出，可以强制返回 JSON

· 体积小，e4b 版本普通笔记本就能跑

3. Folium：Python 地图库

Folium 是 Python 交互式地图库，基于 Leaflet.js，几行代码就能生成带标记的地图。

三、核心思路：四步流水线

整个项目的工作流程：

用户输入地点名称和数量
↓
本地 Gemma 4 生成结构化 JSON
↓
自动验证坐标和字段完整性
↓
Folium 渲染成交互式 HTML 地图

第一步：让 AI 输出 JSON

关键是写好 System Prompt，强制模型只返回 JSON：

system_prompt = """You are a geography assistant.
You ALWAYS respond with valid JSON only.
No markdown, no explanations.
Each location has: name, name_zh,
latitude, longitude, description,
category."""

大模型有时候会"不听话"，在 JSON 外面包一层 markdown 代码块，代码里要做清理：

content = content.replace("```json","")
content = content.replace("```","").strip()

第二步：自动验证数据

AI 生成的坐标可能是错的（"坐标幻觉"）。验证器检查每个地点：

· 六个字段是否齐全

· 坐标是否是数字、范围是否合法

· 坐标是否在目标地点合理范围内

第三步：分类着色

定义了 12 种地点分类，每种对应一个颜色：

分类颜色
校门红色
地标建筑蓝色
教学设施绿色
体育设施橙色
商业街紫色

第四步：渲染地图

用 Folium 生成地图，添加标记、弹窗、图例、标题栏，保存为 HTML 文件。双击打开就是交互式地图。

四、踩了三个大坑

坑 1：AI 给的坐标偏差 3.5 公里

第一次让 AI 生成学校坐标，它给了 34.40°N, 113.73°E。高德地图一查，实际是 34.401422°N, 113.765004°E——经度差了 3.5 公里！

教训：AI 生成的精确坐标一定要用地图服务验证。

坑 2：模型太大，电脑带不动

一开始想跑 26B 参数模型，8GB 内存笔记本直接卡死。换成 e4b 版本后流畅运行。

8GB 内存用 e2b，16GB 用 e4b（推荐），有独显可以试 26B。

坑 3：Ollama 服务没启动

第一次运行一直提示"无法连接"，排查半天发现 Ollama 服务没在后台运行。Windows 检查任务栏图标，Linux 手动运行 ollama serve。

五、离线模式：100% 可用

为了防止模型出问题，加了离线模式，不调用 AI，直接使用内置的 12 个经过人工核实的真实地点：

python sias_map_agent.py --offline

这个设计保证项目 100% 可用，不会因为 AI 故障完全瘫痪。

六、从脚本到 Web App

做完本地脚本后，又升级成了网页应用。用户打开网页，输入地点名称，选择 Demo 或 AI 模式，点击生成就能看到地图。

技术栈纯 HTML + Tailwind CSS + JavaScript + Leaflet.js，单文件零依赖。部署到 Vercel 后任何人打开链接就能使用。

七、你可以怎么做

如果你也想做类似项目，建议按这个顺序：

1. 安装 Ollama，下载 gemma4:e4b

2. 安装依赖：pip install requests folium

3. 先跑离线模式确认地图正常

4. 再试 AI 模式观察模型输出

5. 用高德地图核对坐标

6. 最后部署上线分享给同学

整个过程 AI 辅助下大约需要半天时间。

写在最后

做完这个项目最大的感受：本地大模型的能力被严重低估了。

它不需要联网、不花 API 费用、数据不离开你的设备，能力已经足够完成很多实际任务。

关键不是工具有多强，而是你能不能把工具组合起来解决真实问题。
